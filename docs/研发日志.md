# FinVL-MAS 研发工作日志

> 本文档记录 FinVL-MAS 项目的研发过程、设计思考、遇到的困难及解决方案。

---

## 一、项目概述与研究动机

### 1.1 核心洞察

本项目的出发点来自一个简单但深刻的观察：**专业交易员看的是图表，而不是原始数字。**

一个有经验的交易员可以在几秒钟内从K线图上识别出头肩顶、趋势线突破、量价背离等形态——这些都是空间-关系型的视觉模式，它们从渲染后的图表中涌现，而非直接存在于原始 OHLCV 数值序列中。

然而现有的金融 AI 系统几乎完全忽略了这个视觉推理维度：
- **数值序列模型**（PatchTST, TimesNet 等）直接处理原始价格向量，丢失了图表的空间结构信息
- **通用 VLM 方案** 虽然能"看"图表，但只是把截图喂给通用视觉模型，没有结构化的几何理解
- **多智能体金融系统**（FinCon, TradingAgents）主要处理文本数据，不涉及视觉推理

### 1.2 科学问题

> 结构化的图表视觉推理——将图表几何特征（趋势线、支撑/阻力位、K线形态、图表形态）作为一等语义层来提取和推理——能否捕获纯数值模型遗漏的决策相关信息？

### 1.3 为什么不是简单的 A+B

最大的风险是被审稿人认为这只是 "MAS4TS（时序视觉推理）+ R&D-Agent(Q)（金融研发流程）= FinVL-MAS" 的机械组合。

避免这个陷阱的关键策略：
1. **以认知论文为引导**，而非系统组合——论文的核心主张是关于交易员视觉认知的计算化，而非两个框架的拼接
2. **视觉推理必须超越 MAS4TS**——从通用时序锚点提取升级为金融图表几何解析
3. **智能体分解必须有认知依据**——每个智能体对应交易员认知的一个可辨识方面
4. **R&D 循环必须产出新证据**——发现哪些视觉模式在哪些市场条件下最有效

## 二、技术架构设计

### 2.1 整体流程

```
任务规范 → 图表渲染 → 视觉分析 → 多智能体推理 → 决策形成 → 回测验证 → 反思分析 → [循环]
```

### 2.2 关键设计决策

#### 决策 1：混合视觉分析（规则 + VLM）

**思考过程**：纯 VLM 方案的问题是幻觉和精度不足；纯规则方案的问题是无法识别复杂形态。

**解决方案**：采用混合架构——
- 规则路径：基于 scipy/numpy 的趋势线检测、支撑阻力聚类、K线形态分类（可靠但简单）
- VLM 路径：将渲染的图表发送给 VLM，获取整体形态解读和自然语言描述（灵活但可能不精确）
- 融合：规则提供"基准"几何特征，VLM 提供整体解读，分歧作为不确定性信号

#### 决策 2：五智能体认知分解

**思考过程**：单一 LLM 将感知、模式匹配、上下文判断、风险评估、决策形成混为一谈。交易台将这些分解为专家角色。

**设计**：
| 智能体 | 认知角色 | 类比 |
|--------|---------|------|
| ChartAnalyst | 视觉感知 | 技术分析师读图 |
| PatternReasoner | 模式识别 | 形态分析师解读 |
| EventAnalyst | 上下文整合 | 基本面研究员 |
| RiskController | 风险评估 | 风控官 |
| DecisionPM | 决策形成 | 投资组合经理 |

#### 决策 3：门控共享记忆

**思考过程**：智能体之间如何有效通信？简单的串联传递会导致信息瓶颈；完全连接的通信会产生噪声。

**解决方案**：复用 MAS4TS 的门控交叉注意力（GatedCrossAttention），每个智能体通过置信度加权的门控机制向共享记忆写入：
```
M ← (1 - α) · M_prev + α · Com(M, h_agent)
```
高置信度的智能体对共享记忆有更大影响力。

#### 决策 4：结构化图表几何表示

**思考过程**：图表几何应该用什么数据结构表示？自由文本描述太模糊；纯数值向量失去语义。

**解决方案**：定义 `ChartGeometry` 数据类，包含类型化的子结构：
- `TrendLine`：方向、斜率、R²、起止位置
- `PriceLevel`：价格、类型（支撑/阻力）、强度、触及次数
- `CandlePattern`：形态类型、位置、显著性、暗示方向
- `ChartFormation`：形态类型、阶段、目标价、置信度
- `VolumeSignal`：类型、位置、暗示
- `RegimeState`：趋势/震荡/波动/平静

### 2.3 代码复用策略

**从 MAS4TS 复用**：
- `BaseAgentTS` → 适配为 `BaseFinAgent`（保留 `process()` 接口、置信度输出）
- `GatedCrossAttention` → 直接复用（通信机制的核心）
- `ToolManager` 模式 → 适配为金融工具注册
- VLM 集成模式 → 适配为金融图表分析

**从 R&D-Agent 复用**：
- `LoopBase`/`LoopMeta` → 工作流循环引擎
- `Scenario` 抽象 → 场景定义模式
- `Hypothesis → Experiment → Feedback → Trace` → 实验追踪
- `T()` 模板系统 → Prompt 渲染

**全新构建**：
- 图表渲染管道（基于 mplfinance / matplotlib）
- 图表几何提取（趋势线、支撑阻力、K线形态、图表形态）
- 5个金融专家智能体
- 回测框架
- GUI 仪表板
- HTML 报告生成器

## 三、工程实现过程

### 3.1 Phase 1：项目骨架搭建

**工作内容**：
- 创建 `environment.yml`、`pyproject.toml`、`Makefile`
- 搭建完整包结构：`finvl/core/`, `agents/`, `visual/`, `evaluation/`, `workflow/`, `utils/`
- 从 MAS4TS 适配基础智能体类和门控通信模块

**遇到的问题**：MAS4TS 的 `BaseAgentTS` 继承自 `nn.Module`（含可训练参数），但 MVP 阶段的智能体是基于 prompt 的，不需要梯度。

**解决方案**：创建轻量级 `BaseFinAgent`（纯 Python 类），保留 `process()` 接口和置信度输出机制，将可训练的 `GatedCrossAttention` 保留在 `communication.py` 中供后续集成。

### 3.2 Phase 2：数据模型与场景定义

**工作内容**：
- 定义 15+ 领域类型（枚举 + 数据类）
- 创建 `FinVLScenario` 场景规范
- 实现 OHLCV 数据加载器（含数据质量验证）

**设计权衡**：用 `dataclass` 还是 `pydantic.BaseModel`？

**决定**：核心类型用 `dataclass`（轻量、无额外依赖），数据模式用 `pydantic`（验证）。这样核心模块不强依赖 pydantic。

### 3.3 Phase 3：图表渲染与几何提取

**这是项目的技术核心。**

**图表渲染**：
- 用 `mplfinance` 渲染标准K线图+成交量
- 提供 matplotlib 回退方案（环境兼容性）
- 支持 SMA、布林带等叠加指标

**几何提取**：
- 趋势线检测：在局部极值点上做线性回归，R² > 0.3 才保留
- 支撑阻力：价格聚类算法，容差 = 价格范围 × 2%
- K线形态：基于实体/影线比率的规则分类（十字星、锤头、吞没等）
- 图表形态：基于极值点的双顶/双底、三角形检测
- 成交量信号：放量/缩量、量价背离检测
- 市场状态分类：基于20日波动率和趋势强度

**困难**：
1. 趋势线检测的参数敏感性——`order`（局部极值窗口）太小则噪声过多，太大则遗漏重要转折
2. 支撑阻力的容差选择——固定百分比在不同价格量级的股票上效果差异大

**解决方案**：
1. `order=5` 作为默认值，通过配置可调
2. 容差用价格范围的百分比（自适应），而非固定值

### 3.4 Phase 4：多智能体编排

**工作内容**：实现 5 个专家智能体 + 编排器

**关键设计**：智能体间的信息流是单向顺序的（ChartAnalyst → PatternReasoner → EventAnalyst → RiskController → DecisionPM），每个智能体通过共享记忆读取上游结果并写入自己的分析。

**PatternReasonerAgent 的模式库**：内置了 14 种常见图表形态的历史胜率数据（来自技术分析文献），用于对检测到的形态进行概率评估。

**RiskControllerAgent 的风险模型**：
- 基于 ATR(14) 的止损计算
- 利用支撑位调整止损
- 基于波动率分位数的仓位缩放
- 风险等级自动分类（低/中/高/极端）

**DecisionPMAgent 的决策融合**：
- 置信度加权的方向评分
- 风险过滤（高风险 + 低收益风险比 → 回避）
- 矛盾检测（看涨 vs 看跌的智能体自动标记）

### 3.5 Phase 5：共享记忆

**实现**：`SharedMemory` 类提供：
- 置信度加权写入（高置信度覆盖低置信度）
- 历史追踪（每个 key 的前值保留）
- 矛盾检测（检查 bias 类 key 是否存在看涨/看跌冲突）

### 3.6 Phase 6-7：回测与消融实验

**回测器设计**：向量化回测，支持：
- 交易成本（默认 15bps）
- 滑点（默认 5bps）
- 执行延迟（默认 1天）
- 净值曲线生成

**金融指标**：Sharpe比率、年化收益、最大回撤、Calmar比率、IC、Rank IC、方向准确率、胜率、盈亏比

**消融配置**：通过 YAML 配置文件切换组件开关，无需修改代码。

### 3.7 Phase 8：论文骨架

**LaTeX 结构**：标准 NeurIPS 格式，6个章节 + 附录。Abstract 和 Introduction 已有完整初稿。Method 部分包含公式化的问题定义和系统描述。

## 四、GUI 与可视化

### 4.1 Gradio 仪表板

**设计目标**：提供美观、交互式的分析界面，不是简单的命令行输出包装。

**功能**：
1. **图表分析标签页**：上传 CSV → 交互式 Plotly K线图 + 几何覆盖 + 智能体管道可视化 + JSON 输出
2. **实验结果标签页**：加载实验输出目录 → 关键指标卡片 + 完整 JSON
3. **关于标签页**：系统架构说明和引用信息

**技术选型**：Gradio 4.0+ with `gr.Blocks`，主题用 `gr.themes.Soft`（teal 主色调），Plotly 做交互图表。

### 4.2 HTML 报告生成器

**设计目标**：生成自包含的 HTML 报告（无需服务器），可直接在浏览器打开。

**技术方案**：
- 内联 Plotly CDN（唯一外部依赖）
- 暗色主题（Tokyo Night 配色）
- 自适应网格布局
- 指标卡片 + 净值曲线 + 消融对比图 + 市场状态分析

## 六、实验设计

### 6.1 核心实验问题

1. 视觉图表推理是否有用？（A1 vs A2）
2. 多智能体是否优于单智能体？（A1 vs A4）
3. 门控共享记忆是否有帮助？（A1 vs A5）
4. 图表几何在波动市场中是否特别有价值？（市场状态分析）
5. 系统在考虑交易成本后是否仍然有效？（有/无成本对比）

### 6.2 金融严谨性保障

- **无泄漏**：所有特征仅用历史数据计算
- **时间点一致**：图表渲染仅用决策日期之前的数据
- **时序划分**：严格的训练/验证/测试时间分割
- **交易成本**：默认 15bps 往返成本
- **执行延迟**：默认 1 天延迟（保守假设）

## 八、关键教训

1. **复用优于重写**：从 MAS4TS 和 R&D-Agent 复用成熟模式，大幅加速开发
2. **类型系统是设计工具**：先定义 `ChartGeometry` 等类型，再写实现，保证模块间接口清晰
3. **混合方案优于纯方案**：规则+VLM 的混合视觉分析比任何单一方案都更可靠
4. **消融驱动设计**：从论文需要的消融实验反向设计系统的模块化结构
5. **认知隐喻不是修辞**：将智能体映射到交易员认知角色，既指导系统设计，也强化论文叙事

## 九、数据管道与三模态对齐（新增）

### 9.1 参考 FinCon 的数据策略

研究 FinCon 论文后，提取了以下关键数据设计决策：
- **6种数据源**：新闻（Reuters/Alpaca）、10-K/10-Q年报季报（SEC EDGAR）、Zacks研究报告、OHLCV价格（yfinance）、ECC电话会议音频
- **时间敏感性分层**：年报（长期）、季报/ECC（中期）、新闻（即时），不同衰减率
- **42支股票池**：筛选标准为新闻数量 > 800条
- **时间划分**：LLM训练 2022.01-2022.10，测试 2022.10-2023.06

### 9.2 FinVL-MAS 三模态数据设计

区别于 FinCon 的纯文本+数值方案，FinVL-MAS 需要三模态对齐：

| 模态 | 内容 | 格式 | 对齐方式 |
|------|------|------|---------|
| 时序 | OHLCV + 技术指标 | `TimeSeriesData` (JSON) | lookback窗口截止到 decision_date |
| 图像 | K线图+成交量+叠加指标 | PNG文件 + `ChartImageData` 元数据 | 从相同时序窗口渲染 |
| 文本 | 新闻、财报、分析师报告 | `TextualContext` (JSON) | 仅含 decision_date 之前发布的数据 |

**核心数据单元**：`DecisionSample` — 单个决策时间点的三模态对齐样本。

**存储格式**：JSONL（每行一个样本）+ 图表图片目录。这比单一大JSON文件更适合流式处理和部分加载。

### 9.3 数据处理管道

实现了完整的数据管道 `pipeline.py`：

```
原始OHLCV → 技术指标计算 → 图表渲染 → 文本收集 → 标签计算 → 对齐打包 → JSONL输出
```

关键设计：
1. **无泄漏保证**：所有数据（时序、图表、文本、指标）严格遵守 point-in-time 约束
2. **标签计算**：前瞻收益率（1日、3日、5日）+ 方向分类（up/down/flat，阈值 ±0.5%）
3. **增量处理**：支持按日期范围生成，不需一次处理全部数据

### 9.4 合成测试数据

为开发和调试实现了完整的合成数据生成器 `synthetic.py`：
- **价格生成**：几何布朗运动 + 波动率regime切换（calm/normal/volatile）
- **合成新闻**：基于近期收益率的情感相关新闻模板（6种看涨、6种看跌、4种中性）
- **合成财报**：MD&A风格的季度报告摘要
- **合成分析师报告**：评级 + 目标价

成功生成 88 个三模态样本，验证了全管道的正确性。

### 9.5 首次实验运行

使用合成数据完成了全管道验证：
- **主实验**：50个测试日期，5智能体管道完整运行，Sharpe = -1.21
- **消融实验**：A1-A6 五个配置对比
- **基线对比**：Buy-and-Hold (Sharpe=0.77), SMA交叉 (-0.28), 动量 (0.85)
- **市场状态分析**：quiet/ranging/trending_up/trending_down 四种状态

结果符合预期（合成数据上不追求好结果，重点是验证管道正确性）：
- 系统能正确检测智能体间的分歧（ChartAnalyst看涨 vs PatternReasoner看跌）
- 各智能体置信度合理分布
- 回测器正确处理交易成本和执行延迟
- HTML报告成功生成
