\section{Experiments and Reproducibility Audit}
\label{sec:experiments}

\subsection{Evidence Policy}

We separate three evidence levels. A \emph{unit audit} checks one deterministic contract such as factor execution or date filtering. A \emph{component smoke test} loads the named checkpoints and exercises one real forward/backward path, but is not a trading result. A \emph{financial result} requires a checkpoint manifest and synchronized cost-adjusted daily returns for every asset in a locked arm/seed run. The evaluator never promotes either of the first two levels into the third and never substitutes a proxy for a missing run.

This distinction matters because the active implementation migrated from earlier Qwen2.5 prototypes to a Qwen3.5-9B student and Qwen3.5-27B teacher. Archived return tables without the new checkpoint manifests and daily PnL are not evidence for the migrated method and are excluded from this paper's claims.

The binary factor artifact has SHA-256 \texttt{51c338c9\ldots e550}. Expressions and metadata are decoded only inside the reproduction branch; no JSON manifest or hosted factor API is required. The router checkpoint additionally stores the ordered factor names, so a checkpoint cannot silently attach weights to a permuted library. Its input is the 157-value MAD-normalized current factor state padded to 768 dimensions plus a four-way regime one-hot, and the observed action contains exactly 15 IDs.

The dual-model smoke test is deliberately narrow but real: it loads the local Qwen3.5-9B and Qwen3.5-27B checkpoints, disables thinking for the deployable JSON completion, snapshots the round-start LoRA adapter, evaluates teacher, student, and reference distributions on the identical student completion, performs one optimizer step, and asserts finite JSD/teacher--student KL/reference KL. It validates the claimed software path, not strategy profitability or convergence.

\subsection{Locked Financial Evaluation}

The preregistered protocol uses AAPL, GOOGL, NVDA, and JPM; equal 25\% initial-capital weights; USD~1{,}000{,}000 initial capital; 15\,bps transaction cost; 5\,bps slippage; one-day execution delay; and seeds 42, 123, and 456. The retrospective point-in-time window is January 2025 through May 2026. Since Qwen3.5 was released after this window began, point-in-time prompts do not establish model-weight non-contamination. A later true-forward window is required for that claim.

The locked matrix contains full, no-OPD, vanilla GKD, no-memory, no-OPD/no-memory, uniform-credit, no-reference-KL, fixed-router, and no-execution-guard arms. Each arm/seed directory must contain a manifest whose arm, seed, and split match the matrix; a resolvable checkpoint; and one finite, unique-date \texttt{daily\_returns.csv} per asset. From the inner-aligned dates, the evaluator constructs synchronized portfolio PnL and recomputes cumulative return, Sharpe, drawdown, and Calmar. It also produces fixed-seed 20-day moving-block Sharpe intervals, paired block tests against the full system, and Holm-adjusted $p$-values.

At revision time, none of the 27 Qwen3.5 arm/seed manifests was complete. The strict evaluator therefore reports all 27 runs as missing and emits no portfolio comparison. We do not reproduce the former macro-averaged values 60.9\%, 1.41, and 3.30 here: those were arithmetic means of archived per-asset metrics, not synchronized portfolio return, Sharpe, or Calmar, and their originating Qwen3.5 daily-PnL records are absent.

\subsection{What the Current Evidence Establishes}

The audits establish that the frozen 157-factor library is executable, the ordered top-15 router is wired into DecisionPM, memory retrieval respects outcome availability, coalition replay uses the same horizon, and the named 9B/27B checkpoints support the claimed one-step token update. They also establish that the new evaluator fails closed when financial evidence is incomplete. They do \emph{not} establish superior return, statistical significance, robustness across markets, or a causal benefit from OPD, memory, or routing. Those claims are reserved for the completed locked matrix.
