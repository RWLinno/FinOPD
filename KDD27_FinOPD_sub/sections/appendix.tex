\section{Reproducibility and Protocol Details}
\label{sec:appendix_details}

\subsection{Specialist and Policy Contract}

The reproducible decision path has four structured specialists and one token policy. ChartAnalyst extracts deterministic OHLCV geometry; PatternReasoner interprets those typed patterns; EventAnalyst consumes only supplied point-in-time events (empty in the OHLCV-only runs); and RiskController produces exposure constraints. Their decision-local memory is cleared after every date. A deterministic specialist proposal and complete attributed trace are then serialized into the Qwen3.5-9B prompt. Qwen3.5-9B is the only component that emits trainable policy tokens.

The student snapshot contains asset, date, current price, one- and five-day return, 20-day annualized volatility, volume, specialist action/confidence/rationale, the attributed trace, and at most five outcome-matured episode summaries. The output must contain \texttt{action}, \texttt{confidence}, \texttt{position\_size\_pct}, \texttt{conviction}, \texttt{rationale}, \texttt{key\_evidence}, and \texttt{risks}. Thinking is disabled for deterministic JSON generation. The parser clips confidence to $[0,1]$ and exposure to $[0,0.30]$, forces zero exposure for hold, and uses the specialist proposal if parsing fails.

After the outcome horizon closes, the Qwen3.5-27B prompt prepends a canonical JSON object containing only \texttt{utility}, \texttt{cumulative\_return}, \texttt{mdd}, \texttt{cvar\_loss}, and \texttt{turnover}. The teacher is frozen and evaluated on the exact student-generated completion. It never receives a raw future price path, future chart, or future OHLCV array.

\subsection{Frozen Factor Artifact}

Alpha-Factor Evolution is completed before OPD. The reproduction branch packages 157 ordered executable records in \path{src/finvl/factors/frozen_factors.bin}; neither a JSON factor manifest nor a factor-serving API is distributed. The loader verifies artifact version, count, order, and content hash before compiling expressions in the constrained DSL. The checkpoint stores the same ordered factor names, preventing a valid weight tensor from being applied to a permuted library. The audited artifact hash is \texttt{51c338c93163876f\allowbreak d0a01f8919993e2c\allowbreak fa464032bdced8b2\allowbreak fc55687530c1e550}.

The executability audit evaluates all records on a 500-bar OHLCV slice, sanitizes non-finite arithmetic, and asserts a finite vector for each record. All 157 pass; 121 vary on this slice. A constant result is not treated as a globally useless factor because some expressions require optional fields absent from OHLCV-only data. These counts are software evidence, not a claim of alpha profitability.

\subsection{Locked Run Artifacts}

For arm $a$ and seed $s$, the evaluator reads \path{RUNS/a/seed_s/run_manifest.json}. The manifest must declare the exact arm, seed, test split, and checkpoint. Relative checkpoint paths resolve against that run directory. Each asset directory must contain \path{daily_returns.csv} with unique in-window dates and finite \path{net_return}. Any mismatch marks the entire run missing.

For a complete run, asset series are inner-aligned by date and combined with the declared capital weights. Portfolio return, equity, drawdown, cumulative return, annualized Sharpe, maximum drawdown, and Calmar are recomputed from this synchronized series. The evaluator writes both asset and portfolio daily PnL, a metrics JSON, a fixed-seed 20-day moving-block Sharpe interval, paired block $p$-values against the full arm, and Holm-adjusted values. With \texttt{--strict}, any missing run returns a nonzero exit code.

\section{Expanded Limitations and Ethical Discussion}
\label{sec:limitations}

\paragraph{Incomplete financial evidence.}
The implementation audits do not establish profitable trading. The locked matrix currently lacks all 27 required arm/seed manifests, so there is no synchronized Qwen3.5 portfolio result, confidence interval, or causal mechanism comparison to report. Earlier archived metrics used a different backbone and cannot be relabeled as results of this system.

\paragraph{Temporal validity.}
The proposed retrospective window begins before Qwen3.5 was released. Point-in-time prompts control runtime leakage but cannot rule out knowledge encoded in model weights. A true-forward evaluation after the complete model/data cutoff, plus no-text and de-identified-ticker controls, is required for a stronger temporal claim.

\paragraph{Model and utility risk.}
The teacher depends on a designed five-scalar hindsight summary and utility, so misspecification can transfer undesirable preferences even when the information boundary is correct. Reference KL limits local adapter drift but does not guarantee safety under structural breaks. This research prototype is not investment advice; deployment requires licensed point-in-time data, human approval, exposure limits, and market-impact, liquidity, and operational-risk testing.
